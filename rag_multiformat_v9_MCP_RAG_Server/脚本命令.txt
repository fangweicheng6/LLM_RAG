一、环境准备（首次使用）
------------------------------------------------------------
D:\RAG\rag\Scripts\activate.bat

python -m pip install third_party\ragas-0.4.3-py3-none-any.whl

二、知识库入库
------------------------------------------------------------
python -m ingestion.ingest                     # 全量：重新解析全部文件后整份重建索引，再把向量库对账到索引
python -m ingestion.ingest --incremental       # 增量：只重解析新增/内容变化的文件，并删除已不存在文件的 chunk
python -m ingestion.ingest --incremental --dry-run       # 只列出将新增/重切/删除的文件，不写任何东西
python -m ingestion.ingest --incremental --force-delete  # 允许单次删除超过阈值比例的文件（默认 25% 拒绝）
python -m ingestion.ingest --resume            # 断点续跑：复用中断产物里未变的文件，增删改过的文件会被正确重做（结果与全量重跑一致）
python -m ingestion.clean_chunk [--input xx --output xx --errors xx]   # 分块清洗
python -m ingestion.clean_chunk --incremental [--dry-run] [--force-delete]  # 切片阶段单项版
python -m ingestion.clean_chunk --resume       # 切片阶段断点续跑（单项版）
python -m ingestion.embed_store [--input xx]   # 向量库对账：只嵌入「索引有、库里没有」的 chunk，并删掉多余的
python -m ingestion.embed_store --rebuild      # 忽略库内现有内容，把索引里每个 chunk 强制重新嵌入（换模型/疑似脏库时用）
python -m utils.knowledge_update               # 增量更新辅助（目前为占位模块；实际更新请用 python -m ingestion.ingest --incremental）
python -m utils.index_audit                    # 索引审计：校验 metadata 白名单、快照存在性，并比对向量库与索引的 chunk 集合是否一致

  注：入库不再需要「删掉 chroma 目录重建」。全量与增量共用同一条对账写入路径，
      删除文件后的残留向量会被自动清理；--rebuild 是换 embedding 模型时的显式兜底。

三、服务启动
------------------------------------------------------------
python -m server.start_server --mode socket    # Socket 服务（端口 1234）
python -m server.start_server --mode http      # HTTP 服务（端口 8000）
python -m server.start_server --mode mcp       # MCP stdio（供本地 AI 客户端拉起，一般无需手动运行）
python -m server.start_server --mode mcp-http  # MCP streamable-http（远程客户端，默认 127.0.0.1:8100/mcp）
uvicorn deployment.api_server:app --host 0.0.0.0 --port 8000    # HTTP 等价写法
python -m deployment.rag_server                # Socket 等价写法
start_mcp.bat                                  # 一键启动 MCP（默认 streamable-http: http://127.0.0.1:8100/mcp；本地 stdio 客户端加 --transport stdio）

四、客户端调用
------------------------------------------------------------
python -m client.http_client "问题"            # HTTP 客户端（对应三中的 http 服务）
python -m client.socket_client "问题"          # Socket 客户端（对应三中的 socket 服务）
python -m deployment.rag_client "问题"         # 旧版客户端（与 socket_client 等价，建议用上面的）

四-A、生成开关 / 纯检索对接（详见 docs\对接说明.md；MCP 交接见 docs\MCP对接文档.md）
------------------------------------------------------------
# configs\rag.yaml -> rag.generation.enabled
#   false（当前默认，对接形态）: 不生成回答，answer=null、generation_enabled=false，chunk 在 selected_contexts 中
#   true                       : /chat、socket query、MCP rag_chat 调 LLM 生成最终回答
# 纯检索接口（任何模式下都不生成，供外部系统对接自家 LLM）：
#   HTTP   POST http://127.0.0.1:8000/search   body: {"query": "..."}
#   Socket {"cmd": "search", "text": "..."}
#   MCP    工具 rag_search
# 零 LLM 调用部署：generation.enabled=false + context.selector.enabled=false
#                  + retrieval.multi_hop.enabled=false（router 默认已关；multi-hop 也是 LLM 调用）
